# Sapiens EEG demo

Illustrative N27 brain and simulated EEG signals, not human recordings or
clinical data. Electrodes are placed at the cortex for clarity; real EEG
electrodes sit on the scalp.

## Rebuild and run

Run these commands from the repository root, in order:

```sh
~/.local/bin/micromamba run -p "$HOME/.local/share/sapiens-eeg-viewer/r-env" \
  Rscript sapiens-eeg-viewer/scripts/make_electrodes.R
python3 sapiens-eeg-viewer/scripts/make_data.py
~/.local/bin/micromamba run -p "$HOME/.local/share/sapiens-eeg-viewer/r-env" \
  Rscript sapiens-eeg-viewer/scripts/generate_viewer.R
~/.local/bin/micromamba run -p "$HOME/.local/share/sapiens-eeg-viewer/r-env" \
  Rscript sapiens-eeg-viewer/scripts/make_mri_volume.R
sapiens-eeg-viewer/scripts/serve.sh
```

Open <http://127.0.0.1:8000/web/>. The server hosts `web/`, `public/`, and
`data/` on one origin. Set `PORT` to use another port.

Environment: Fedora Linux 44, R 4.4.3, threeBrain 1.2.0.
The R environment and N27 template were installed previously; N27 is at
`~/.local/share/R/threeBrain/templates/N27`.

## Electrode placement

No verified transform from MNE's standard montage into N27 was available, so
the electrodes use the anatomical-placement fallback in
[`scripts/make_electrodes.R`](scripts/make_electrodes.R). For each assigned
FreeSurfer aparc region in `mri/aparc+aseg.mgz`, it selects the pial vertex
nearest that region's centroid; midline targets use tkRAS x=0. This is
schematic anatomical placement, not a standard 10-20 cortical projection.

Coordinates are FreeSurfer tkRAS, in millimetres, matching the threeBrain
sample-table convention. Each contact is linked to its selected pial vertex
(`SurfaceElectrode = TRUE`) with a 5 mm surface offset and 4 mm radius. The
script retains the original pial coordinates in `Pial_x/y/z` and derives
MNI305 columns with threeBrain's
`apply_transform_points(from = "tkrRAS", to = "MNI305")`.

Placement checks: C3 tkRAS x=-40.37 mm and C4 x=+38.15 mm; Fp1/Fp2 are
anterior, P3/Pz/P4 posterior, and Cz near the top midline. See the labelled
[`top`](web/screenshots/placement-top.png),
[`left`](web/screenshots/placement-left.png), and
[`right`](web/screenshots/placement-right.png) views.

## Renderer and data

The page uses only the standalone threeBrain viewer generated by
[`scripts/generate_viewer.R`](scripts/generate_viewer.R). No alternate or
custom brain renderer is included. The viewer can be controlled through the
same-origin iframe's Time field and Play/Pause checkbox. If direct control is
unavailable, the page follows the viewer's time and asks the viewer's own
controls to be used. On the N27 template, the viewer still does not visibly
colour electrode contacts from the values; the page keeps the default
threeBrain scene and uses the phase-emphasized waveforms to show the signal
changes. The current browser render shows numeric electrode annotations but
not visible contact spheres or time-varying electrode colours, even with
`priority = "sphere"` passed to `set_electrodes`; this remains a limitation.

The MRI panel renders continuous axial, coronal, and sagittal scans through
the actual N27 `mri/brain.finalsurfs.mgz` anatomical volume. Run
[`scripts/make_mri_volume.R`](scripts/make_mri_volume.R) to export its
grayscale voxels and tkRAS geometry locally. Playback continuously sweeps the
three planes through their respective anatomical ranges and linearly
interpolates adjacent voxel planes at the live playhead time. The anatomy is
a static template; only slice positions change. Axial (-70 to +70 mm),
coronal (-65 to +65 mm), and sagittal (-60 to +60 mm) ranges keep all three
planes within visible N27 anatomy from the initial frame. This is not live
MRI acquisition or functional activation data.

[`scripts/make_data.py`](scripts/make_data.py) uses seed `20261127` to create
15 channels at 250 Hz for 20 seconds (5000 samples per channel), event
captions, and 10-Hz viewer values. `ERD_percent` is 8–12 Hz power change from
the rest baseline; `RMS_uV` is the 0.5-second-window RMS. Left-hand imagery
reduces C4 mu power, right-hand imagery reduces C3, and the blink peaks at
Fp1/Fp2. Carrier amplitude varies gradually, with independent colored and
broadband noise, smoothed event transitions, and a brief multi-frequency
frontal muscle burst. These are synthetic signals and should not be mistaken
for physiological recordings.

The trace display uses stacked labelled channels, a shared fixed microvolt
gain, fine time/amplitude guides, and an uncluttered chronological event rail.
It is a visualization of seeded synthetic waveforms, not a medical monitor.
On desktop, the transport and event rail share a compact 106 px footer; short
segment labels preserve space while full event names remain accessible and
the current event caption stays above the controls.
Clinical terminology and amplitude conventions were checked against the
[IFCN glossary of terms used in clinical EEG](https://pmc.ncbi.nlm.nih.gov/articles/PMC6123891/)
and the MNE-Python [ECoG](https://mne.tools/stable/auto_tutorials/clinical/30_ecog.html)
and [sEEG](https://mne.tools/stable/auto_tutorials/clinical/20_seeg.html)
visualization examples. Those sources also emphasize that amplitude depends
on derivation and display gain; this demo labels its gain and simulated data
rather than presenting the traces as clinical recordings.

The trace display starts with a one-second looped pre-roll and grows to a
five-second history, using a shared microvolt scale per visible window with a
one-second grid. C4 is
emphasized during left-hand imagery, C3 during right-hand imagery, and frontal
channels during blink and muscle events. The scale expands to ±100 µV and
explicitly marks when larger peaks are clipped. The selected-channel readout
retains the actual sample value. Traces follow the time read from the
threeBrain viewer.
